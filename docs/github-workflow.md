# GitHub work across devices

Durable state belongs to committed docs, Issues and PRs. Use task, experiment and decision Issue templates from GitHub Mobile or a mobile browser. Put business objective, evidence, acceptance and next action in the Issue before handing it to an agent.

Label taxonomy:
- `type:task`, `type:experiment`, `type:decision`
- `area:business`, `area:data`, `area:runtime`, `area:evaluation`, `area:cost`
- `priority:p1`, `priority:p2`, `priority:p3`
- `status:blocked`, `status:ready`

Label definitions are documented here and in templates; if absent create them in repository Issues → Labels before applying. PRs link the issue and include executed checks plus pending validation.

Optional GitHub Project: create a user-owned project, add this repo, and use Backlog / Ready / In Progress / Review / Done. Add links to Experiment issues and architecture decisions. A Project is not required for runtime or initialization.

Mobile actions: create/triage task, review PR, inspect committed experiment summary, make small doc corrections and record next decision. Training and large coding use Codespaces/Dev Containers. Avoid leaving the next action only on one PC.
